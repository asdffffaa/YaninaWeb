# Yanina Korinenko — сайт кондитерской школы

React 19 + TypeScript + Vite. Отдельные макеты для телефона и компьютера, общий каталог и корзина. Внешний вид основан на Figma; исходная геометрия находится в `src/design`.

## Запуск

- Готовая сборка: `START-SITE.cmd` или `node server.mjs`.
- Сервер выводит адрес компьютера и адрес телефона в той же локальной сети. По умолчанию порт 5173, интерфейс `0.0.0.0`; переопределение через `PORT` и `HOST`.
- Разработка: `npm ci`, затем `npm run dev` (для телефона: `npm run dev -- --host 0.0.0.0`).
- После изменений: `npm run build`. Папка `dist` содержит готовую версию.
- Для серверных тестов требуется Node.js 22.18+ или 24+. Сервер использует только встроенные модули Node.

## Структура

- `src/App.tsx` — маршрутизация, корзина и отложенная загрузка страниц/окон.
- `src/components/DesktopHome.tsx` — сборка компьютерной главной.
- `src/components/mobile/MobileHome.tsx` — сборка мобильной главной; интерактивные секции вынесены в отдельные файлы.
- `src/components/ProductRow.tsx`, `FAQItem.tsx` — общие элементы обеих версий.
- `src/data` — товары, ответы FAQ и фильтры техкарт.
- `src/design` — используемые компоненты и стили Figma. Порядок CSS в `main.tsx` важен: геометрия перед переопределениями.
- `public` — исходные локальные изображения, шрифты и оптимизированные WebP. Оригиналы сохранены для дальнейшего редактирования.
- `scripts/finalize-build.mjs` — исключение неиспользуемых медиа из сборки, подготовка Brotli/gzip. Динамически создаваемые имена новых файлов должны присутствовать в коде целиком, как у сертификатов.
- `src/lib` — проверяемые отдельно правила восстановления корзины и подсветки навигации.
- `src/components/CheckoutPage.tsx` — общее состояние формы: e-mail, согласия, способ оплаты и мобильный шаг сохраняются при изменении ширины окна.
- `tests` — модульные, HTTP- и браузерные проверки; отдельные статические проверки Python-бота.

## Проверки

```sh
npm run build
npm test
npm run format:check
npx playwright install chromium
npm run test:browser
# Дополнительно, если установлен Python:
npm run test:bot:static
```

`npm run format` форматирует прикладной код, CSS, сервер и тесты. Экспортированная геометрия Figma исключена из форматирования. TypeScript проверяет строгие типы и неиспользуемые переменные/параметры.

## Поведение

Браузерные тесты сначала собирают проект, затем запускают готовую версию на порту 5187. Они проверяют ширины от 320 до 2560 px, навигацию, формы, корзину, карточки, FAQ, анимации и наличие изображений после оптимизации сборки. При ошибках сохраняются снимок экрана и trace в `test-results`, отчёт — в `playwright-report`. Для уже установленного Chromium можно задать абсолютный путь в `PLAYWRIGHT_CHROMIUM_EXECUTABLE`.

Восстановлен оригинальный дизайн до аудита: компьютерный холст 1920 px, мобильный 402 px, прежние пропорции, отступы, карточки и масштабирование. Мобильный макет используется до 767 px. Экспериментальные растягивание секций, перестройка колонок и меню «Ще» отменены по замечанию пользователя. Адаптация без уменьшения шрифтов пока не завершена: её нельзя считать выполненной за счёт изменения исходного дизайна.

Корзина сохраняется локально; при недоступности хранилища продолжает работать в памяти. Модальные окна управляют фокусом и закрываются по Escape. Каталог сохраняет фильтры, раскрытие и плавное сворачивание. Анимации учитывают `prefers-reduced-motion`.

Мобильные шаги меняются каждые 5 секунд; после ручного выбора следующий переход также через 5 секунд. Таймер приостановлен вне экрана и в скрытой вкладке. Линия прогресса рисуется через transform без постоянных перерисовок React.

Сервер отдаёт Brotli/gzip при поддержке браузером, использует ETag и длительное кеширование только для файлов с хешем содержимого. HTML всегда перепроверяется, отсутствующие файлы возвращают 404.

## Ограничения продукта

Платёжный API и автоматическая выдача материалов пока не подключены. Форма сообщает об этом и предлагает связаться в Telegram. Цены, программы и часть карточек — существующие демонстрационные данные; оптимизация их не заменяет реальным платёжным процессом.

Для Python-бота добавлены офлайн-проверки синтаксиса, имён обработчиков и соответствия меню текстам. Они не проверяют подключение к Telegram или реальную выдачу материалов. Подробности аудита — в `docs/refactoring-audit.md`.
